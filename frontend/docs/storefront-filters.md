# Фильтры каталога

Общий дизайн-код: `storefront-system.css` + `storefront-filters.css`. На ПК панель слева, на телефоне — доступная боковая панель с клавиатурным фокусом, Escape, блокировкой прокрутки и общей анимацией. Неработающий крестик отсутствует; мобильная панель закрывается кнопками «Готово»/«Показать товары» или Escape.

`GET /products/filters` возвращает категории опубликованных товаров, заполненные назначения/особенности и диапазон цен. `GET /products` принимает `category`, `purpose`, `feature` (несколько значений через запятую), `minPrice`, `maxPrice`, `inStock=true`, `sort`, `search`, `page`, `limit`. Внутри группы — ИЛИ, между группами — И. Цена соответствует `basePrice`, отображаемой карточкой. Наличие учитывает только активный вариант и остаток **за вычетом резерва**. Фильтрация и сортировка происходят в БД до пагинации; одинаковые значения сортировки дополнены ID для стабильных страниц. Некорректные параметры возвращают 400, перевёрнутый диапазон отклоняется также в интерфейсе.

Сброс, снятие отдельных фильтров, перезагрузка, внешние ссылки и переходы назад/вперёд используют параметры URL. Цену применяют отдельной кнопкой/Enter, чтобы не перезагружать каталог на каждой введённой цифре.

Назначения и особенности хранятся в `Product.purposes/features` (массивы строк, до 20 значений по 80 символов), редактируются в админке через запятую. Категории — настоящие связи каталога, не текстовый поиск по их названию. Поле назначения не угадывается по общему рекламному описанию.

Миграция: `20260916090000_catalog_filters`. Консервативный скрипт `backend/scripts/normalize-storefront-filters.cjs` обрабатывает только исходный `SB-LIVE-*` импорт: явные гели/ножницы/фрезы, признаки из названий. Существующие категории и заполненные пользовательские свойства сохраняются; товары с другой ручной классификацией пропускаются. Цена, остатки и изображения не меняются. Для будущих товаров менеджер заполняет проверенные свойства вручную; согласовать характеристики из 1С отдельно.

Проверки: `frontend: npm run smoke:storefront-filters`, `backend: npm test -- --runInBand catalog-filters.spec.ts`. Browser smoke использует только чтение реального каталога, не создаёт товаров/заказов; проверяет комбинации, сортировку на разных страницах, валидацию, URL, мобильное закрытие и ширину контейнера.

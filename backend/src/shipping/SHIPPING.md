# Доставка сайта: безопасный локальный режим

Внешние запросы разрешены только при `STOREFRONT_EXTERNAL_CALLS_ENABLED=true`.
Отсутствующее значение, `false`, `1`, `TRUE` не разрешают запросы, включая OAuth.
До приёмки интеграций на VPS оставлять флаг выключенным. Тесты используют только
подменённый `fetch` и Prisma; настоящие службы и база данных в них не вызываются.

## Публичный контракт

- `GET /api/v1/shipping/capabilities`: `{ providers: [...] }`, возможности и сообщения
  для СДЭК и Ozon. Это чтение локальной конфигурации, не проверка подключения.
- `POST /api/v1/shipping/estimate`, заголовок `x-cart-session`, тело
  `{ provider: 'CDEK' | 'OZON_DELIVERY', deliveryMethod: 'COURIER' | 'PICKUP_POINT',
  city, street?, house?, cityCode?, pickupPointCode? }`.
  Возвращает `{ provider, available, amount: number | null, currency: 'RUB',
  requiresConfirmation, canPay, message, estimatedDays?, quoteId?, expiresAt? }`.
- `GET /api/v1/shipping/pickup-points?provider=CDEK&cityCode=44`:
  `{ available, points, message }`. Без внешних запросов список пустой; код/адрес
  ручного выбора не выдаётся за проверенный ПВЗ. Ozon всегда недоступен автоматически.
- `GET /api/v1/shipping/cities?search=Москва`, необязательный `provider=CDEK`:
  `{ provider, available, cities: [{ code, city, region, country, countryCode }], message }`.
  Query search — строка 2–100 символов после trim. Используется справочник
  `/v2/location/cities?city=...&country_code=RU&size=20&page=0`; не более 20 валидных
  уникальных кодов России. Кэш на 5 минут, не более 100 поисковых запросов,
  разделён по среде/реквизитам. Отключённый флаг запрещает и HTTP, и выдачу кэша.
  Frontend должен предлагать выбор города/региона и передавать выбранный code
  в estimate/PVZ; вводить/подбирать выдуманный технический код нельзя.
  Этот маршрут не подключает checkout автоматически и требует проверки
  официального поиска городов на VPS вместе с остальным API СДЭК.

В отключённом режиме `amount=null`, `available=false`, `canPay=false`:
неизвестная стоимость не означает бесплатную доставку. Пользователю сообщается,
что условия будут подтверждены до оплаты. Почтовый индекс не требуется.

## Источник данных и настройка СДЭК

Существующая зашифрованная интеграция экосистемы `CDEK`: `clientId`,
`clientSecret`, `senderCityCode`, `isEnabled`, `environment`.
Реквизиты и ответы авторизации не включаются в публичные ответы/логи.
Адреса запросов фиксированы; пользователь не может подставить произвольный API URL.
Production использует `https://api.cdek.ru/v2`, TEST — `https://api.edu.cdek.ru/v2`.
Авторизация client_credentials кэшируется до истечения токена с запасом 60 секунд.
Запросы ограничены 10 секундами, перенаправления запрещены.

Расчёт: `/calculator/tariff`, тариф 137 (склад—дверь) либо 136 (склад—склад),
код отправителя и получателя, вес в граммах. ПВЗ: `/deliverypoints` по коду города.
Для ПВЗ перед расчётом подтверждается принадлежность выбранного кода списку города.
Вес суммируется **из числового `variant.options.weightGrams` × количество**.
Нет веса хотя бы у одного товара — нет автоматического тарифа. Фиктивные 500 г
и выдуманная формула цены удалены. Нужны реальные веса упакованных товаров;
дополнительную упаковку и размеры необходимо согласовать перед приёмкой на VPS.

Официальный источник для приёмки: [портал API СДЭК](https://apidoc.cdek.ru/).
Текущий портал отдаёт SPA; полную спецификацию через доступный просмотр извлечь
не удалось. Поэтому адаптер не объявляется прошедшим официальную контрактную
приёмку: OAuth, тарифы, поля расчёта, условия договора и ПВЗ проверить на VPS.
Ни одного реального запроса адаптера в этой разработке не выполнялось.

Ozon не подменяется Seller API или тарифами СДЭК. Официальная
[документация Ozon логистики](https://dev.ozon.ru/start/448-Spravochnik-metodov-Seller-API-dlia-Ozon-logistiki/)
в доступном просмотре возвращала цикл перенаправлений. Автоматический адаптер
остаётся отключённым до подтверждения подходящего продукта API и договора.

## Подтверждённый расчёт и оформление заказа

Только полученный корректный тариф сохраняется в `ShippingQuote` на 15 минут:
`sessionHash`, `destinationHash`, `provider`, `deliveryMethod`, `amount`,
`currency`, `expiresAt`, `requestSnapshot` с адресом, весом и отсортированным
`cartItems: [{ variantId, quantity }]`.
Город/код перед расчётом сверяются с результатом поиска СДЭК (для курьера и ПВЗ).
Snapshot хранит канонические `city`, `cityCode`, `region`, `country`, `countryCode`.
Для ПВЗ `pickupPointAddress` и `pickupPointName` берутся только из ответа СДЭК
для выбранного кода и подтверждённого города, не из строк клиента.
Курьерские street/house проверены DTO и обрезаны по краям; существование дома
через геокодер не подтверждается. Квартира не участвует в тарифе и может
дополняться клиентом при оформлении. Заказ должен брать подтверждённый адрес
из Snapshot, а не доверять полю отображаемого address клиентского запроса.
Хеши вычисляются общими `hashCartSession` / `hashShippingDestination`.
Оформление заказа должно проверять срок, сессию, адрес, провайдера/метод и состав
корзины; стоимость берётся из записи сервера, не из суммы клиента.
При смене состава корзины или адреса расчёт повторяется.

## Отправления и склад

Старые POST `/api/v1/shipping/orders/:orderNumber/calculate` и `/ship` защищены
JWT и ролями `ADMIN`, `WAREHOUSE`, `SUPERVISOR`. Посетитель не может вызвать их.
Автоматическое создание отправлений **пока не реализовано**: `/ship` возвращает
503 без записи заказа, изменения статуса/остатков/резервов и без вызовов 1С.
Выдуманный трек-номер удалён. Расчёт тарифа также не означает отправку заказа.

Будущий обработчик подтверждённой перевозчиком отгрузки должен идемпотентно
в одной транзакции потреблять ACTIVE-резерв: `stock -= quantity`,
`reserved -= quantity`, `reservationState = CONSUMED`. LEGACY-заказы не должны
повторно списывать остатки или резерв. Регистрация накладной сама по себе
не доказывает физическую отгрузку. Эта часть остаётся задачей реальной интеграции.

## Локальная проверка

`npm test -- --runInBand shipping.spec.ts cdek.provider.spec.ts`

Проверяются отключённая сеть, отсутствие фиктивных значений, ограничения старых
маршрутов, валидация DTO, неизвестный вес, доступность stock-reserved,
сохранение mock-расчёта и хешей, mock OAuth/кэш/тариф/ПВЗ, ошибки и таймауты.
Самостоятельно backend не перезапускается: портом и общей сборкой владеет основной агент.

# CRM — сохраняемые права файлов и контент-плана

Дата: 24.09.2026. Пакет **BOX-01б2**, часть [плана коробочного решения](CRM_BOXED_RELEASE_PLAN_2026_09_24.md).

## 1. Граница результата

Добавлена сохраняемая политика вложений задач, сделок и публикаций. Она применяется к общему диску, поиску, недавним файлам, корзине, счётчикам, предпросмотру/скачиванию и операциям изменения. Загрузка непосредственно из карточки больше не создаёт промежуточный общедоступный файл.

**Это не включение изоляции отделов во всей CRM.** Профили по-прежнему `DRAFT_ONLY`; рабочий resolver явно сохраняет legacy-область `COMPANY` и персональные запреты. Шесть областей доступа проверены изолированными тестами. Назначать профили сотрудникам до покрытия остальных модулей нельзя.

## 2. Правила доступа

| Файл / операция | Правило |
| --- | --- |
| Личный диск | Только владелец. Роль администратора сама по себе не открывает чужой личный диск |
| Общая библиотека TEAM | Файл без ограничений и связей с карточками остаётся общим для допущенных к диску сотрудников |
| Изменение общей библиотеки | При области записи COMPANY — в пределах разрешения; при более узкой области — только собственные объекты |
| Вложение карточки | Доступ к каждому сохранённому источнику ограничения, не только к текущей открытой карточке |
| Несколько задач/сделок | Пересечение прав всех источников: доступ к одной карточке не открывает файл другой |
| Изменение ограниченного файла | Независимые области чтения и записи должны разрешать все источники |
| Перенос, переименование, отвязка | Ограничения сохраняются; удаление последней ссылки не публикует файл обратно в библиотеку |
| Корзина / восстановление | Те же правила; права не снимаются восстановлением |
| Удалённый источник | Ограничение остаётся, ссылка на родителя становится NULL; файл закрыт, в том числе для COMPANY, до отдельного механизма восстановления |
| Публикации SMM | Доступ через `content_plan.*` только к задачам публикаций; он не заменяет разрешение на сделки или обычные задачи |

Право на файл не расширяется из-за его названия, ID, папки или авторства загрузки. Ограничение источника учитывает текущие права на родителя: перевод ответственного/отзыв доступа влияет на чтение файла. Обычная TEAM-папка сама по себе не является закрытым отделом.

## 3. Хранение и миграция

- `CrmDriveNode.restricted` отличает ограниченные файлы от общей библиотеки.
- `CrmDriveRestriction` хранит неизменяемые `originKind/originId` и nullable FK на задачу/сделку; уникальность по файлу и источнику. Удаление родителя использует `SET NULL`, не удаляет ограничение.
- Миграция `20260924210000_crm_drive_restrictions` добавляет структуру и переносит существующие ссылки `CrmTaskFile/CrmLeadFile` в ограничения. Файлы и существующие ссылки не удаляются/не перемещаются.
- Триггеры PostgreSQL закрепляют источник при добавлении/замене связи, в том числе через bulk insert при создании версии публикации. Триггера снятия ограничений при удалении ссылки нет.
- Старые связанные записи без ограничения не становятся публичными: политика дополнительно проверяет отсутствие активных связей у общего файла. Пустой набор ограничений при `restricted=true` также закрыт.
- Миграция применена **только к существующей локальной БД**, после проверки loopback-адреса; Prisma Client пересобран. Рабочий сервер не затронут.

Перед выпуском: резервная копия, стандартное применение миграций до нового приложения, проверка перенесённых ограничений и согласование восстановления осиротевших файлов. Не выкатывать старый код Drive поверх новой политики: он не применяет фильтры чтения. Не снимать ограничения массово ради совместимости.

## 4. Серверные пути

- `drive-access.ts` — единый Prisma-фильтр. Списки, total и видимый объём используют одну область; скрытые файлы не попадают в счётчики. Проверка реальной квоты остаётся по всему диску, но объём скрытых файлов не возвращается клиенту.
- Прямое чтение содержимого проверяет права до чтения диска и повторно после него. Изменение прав во время I/O не возвращает ранее прочитанный буфер. В API не выдаются `storageKey` или список закрытых источников.
- Массовые операции папок проверяют всех живых потомков, восстановление — весь пакет удаления. При запрещённом элементе операция отклоняется целиком без названий скрытого содержимого. Обход ограничен 10 000 узлами, циклы отклоняются.
- Запись использует транзакции и общий порядок advisory locks: отделы → диск → публикации → задачи (последние блокировки берутся только где нужны).
- Новые `POST /crm/tasks/:id/files/upload`, `/crm/leads/:id/files/upload`, `/crm/content-plan/:id/files/upload` проверяют карточку до записи байтов и повторно внутри транзакции метаданных. Ограниченный файл и ссылка создаются вместе. При ошибке транзакции новые байты удаляются; других файлов это не касается.
- Существующая обычная загрузка в библиотеку сохранена; новые загрузки из карточек её не используют. Прикрепление существующего файла требует права его изменения, поскольку меняет круг доступа. Отвязка не снимает ограничений.
- SMM: область применяется к списку/total, карточке, команде/назначению, изменению, согласованию, архиву/восстановлению и созданию версии. Чтение и изменение/согласование независимы. Недоступный и отсутствующий родитель не различаются по названиям в ошибке.
- При создании версии публикации недоступный исходный файл отклоняет операцию целиком до создания задачи. Новые связи закрепляют дополнительные ограничения через тот же DB-триггер. Вложенная задача публикации возвращает минимальные поля без сырых ID связанных клиента/заказа/сделки; число файлов фильтруется по доступу.

## 5. Интерфейс

- В «Файлах» ограниченный материал отмечен «Доступ по карточкам»; подсказки различают библиотеку и вложения.
- В карточках поясняется правило нескольких источников и сохранение ограничений после отвязки. Загрузка использует один атомарный endpoint, без промежуточного публичного файла.
- Индикатор объёма подписан как объём доступных файлов, а не занятость всего TEAM-диска.
- Ошибки binary-endpoint разбираются как сообщения API: отказ в скачивании/предпросмотре не выводит технический URL вместо пояснения.
- Использованы действующие компоненты и CSS CRM; новые локальные стили не добавлены.

## 6. Локальные проверки

- `backend: npm test -- --runInBand` — **77 наборов / 1 576 тестов**, все прошли. Это unit/изолированные сервисные тесты, не многопроцессная приёмка PostgreSQL или провайдеров.
- Новые `drive-access.spec.ts`, `content-access.spec.ts`: шесть областей, отдельные read/write/approve, несколько источников, отвязка, удалённый родитель, поиск/счётчики, отказ прямого чтения, отзыв прав во время чтения, атомарная загрузка/очистка при сбое, операции папок и клонирование SMM. Проверяется также структура добавочной миграции.
- Backend собирается. Синтаксис локальных `crm-work-contract-check.cjs` и `crm-task-write-boundary-check.cjs` проверен; сами эти DB-сценарии в этом пакете не запускались.
- Контракты frontend прошли: централизованный CSS **236 Vue-компонентов**, **48 владельцев / 817 контролов**, **18 проверок навигации / 9 групп / 49 экранов**.
- `crm-access-readonly-mock.cjs`: 6 сценариев 390/1440 px, включая отказ/восстановление прав и режим руководителя без записи.
- `crm-work-smoke.cjs`: 360/390/1440 px — папки, перенос всей карточкой, загрузка, корзина/восстановление, предпросмотр PDF/текста, подзадачи/прогресс/комментарии/вложения.
- `crm-operations-rendered.cjs`: 390/1440 px — сохранение B2B-заказа, отдела и публикации. Уточнён селектор сотрудника внутри открытой карточки, чтобы не нажимать фоновый переключатель архива.
- `crm-file-access-mock.cjs` прошёл на 390/1440 px: отметка ограниченного файла, отказ предпросмотра/скачивания с понятным сообщением, загрузка из задачи/сделки/публикации, ошибка загрузки без публичного файла, отсутствие переполнения страницы. Скриншоты — `frontend/.screenshots/crm-file-access/`.
- Прямая компиляция `node node_modules/nuxt/bin/nuxt.mjs build` повторно прошла после исправления сообщений файлов. Это не успешный стандартный `npm run build` (см. отдельный долг ниже). Локальные сервисы обновлены: `/crm/` — HTTP 200, API Drive без сессии — HTTP 401.

Браузерные сценарии используют только синтетические сессии и перехваченные API: реальные чтения/записи бизнес-данных и внешние соединения запрещены. Интеграционные тесты с провайдерами не выполнялись по решению владельца.

### Долг общего frontend build

Стандартный `npm run build` останавливается в `prebuild` на проверке типографики витрины: сообщения о `font-family` в `storefront-glass.css` и `font-size` в `storefront-checkout.css`. Эти файлы не менялись в пакете CRM; нужно отдельно сверить CSS и корректность самой проверки, а не считать сообщение доказанным дефектом отображения. Прямая компиляция `node node_modules/nuxt/bin/nuxt.mjs build` проверяет приложение, но не заменяет неуспешный общий gate. Предупреждения о дублях имён старых/новых marketplace-маршрутов, runtime URL шрифтов и крупных чанках также остаются.

## 7. Что остаётся до активации и коробки

1. **BOX-01б3:** Customer 360, конфигурация, заказы/поддержка, экспорт/аналитика и остальные связанные пути — отрицательные тесты прямых ID, списков, счётчиков, поиска и уведомлений. Затем управляемое включение назначений профилей с сохранением DENY; не назначать их раньше готовности этих границ.
2. Самостоятельные области папок/дисков отделов и явное управляемое изменение совместного доступа ещё не реализованы. TEAM-библиотека без связей остаётся общей. Нужен защищённый процесс восстановления доступа к осиротевшим ограничениям с аудитом, без массовой автоматической публикации.
3. Действия Drive пока скрываются по общему разрешению записи, не по отдельному `canWrite` каждой строки. Сервер запрещает неподходящие операции; точное отражение их доступности в кнопках/ПКМ — следующий UX-пакет.
4. Файловая система и БД не составляют одну транзакцию: штатный отказ очищает новые байты, но аварийное завершение процесса между шагами требует отдельного сборщика неподтверждённых файлов. Антивирус, версии файлов, возобновляемые крупные загрузки, настраиваемые квоты и объектное хранилище не добавлены этим пакетом.
5. Реальные гонки транзакций/перевода сотрудника, миграция на копии production и восстановление бэкапа — отдельная серверная приёмка. HTTP-проверки не отменяют необходимость актуальной проверки доступа на всех будущих WS/уведомлениях.
6. TIME (факт/табель/Excel/кадровая 1С), VIDEO, финансовые блокеры, личные чаты и лента остаются в полном плане. Данный пакет не выдаётся за готовность этих модулей или всего рабочего релиза.

# BOX-01б4в1 — ссылки на карточки CRM в чате

Дата: 28.09.2026. Часть [плана коробочного решения](CRM_BOXED_RELEASE_PLAN_2026_09_24.md), продолжение BOX-01б4б.

## Граница пакета

Закрывается обход через **структурированные ссылки на записи** в существующем чате: поиск, прикрепление, история, цитата, превью канала и доставка WebSocket. Членство в канале не даёт права читать любую прикреплённую карточку.

Это не завершение BOX-01б4в, CHAT-01..04 или полного релиза. Назначения профилей остаются **DRAFT_ONLY**, рабочий resolver сохраняет **legacy COMPANY с приоритетом DENY**. Отделы и узкие области проверены на изолированных политиках; их массовая активация не выполнялась.

## Реализация

Единый серверный сервис: backend/src/platform-chat/chat-records.service.ts. Он проверяет действующего внутреннего сотрудника, канал и разрешение соответствующего домена в согласованном снимке БД (RepeatableRead).

| Ссылка | Право и правило чтения |
| --- | --- |
| Задача | crm.read; область задач, без отменённых/удалённых записей |
| Клиент | customers.read; область клиентов, без архивных/удалённых записей; телефон/email не попадают в карточку ссылки |
| Этап продаж | crm.read; активная воронка; при узкой области нужны доступные сделки. Количество рассчитывается только по доступным сделкам, не по всей базе |
| Товар | catalog.read; активный товар вне корзины. Пока нет контракта владельца товара, узкая область не подменяется COMPANY — результат пустой |

- Фильтрация выполняется **до** ограничения поиска в 20 записей. Прикрепление по ID проверяется отдельно и не зависит от попадания в последние 20.
- JSON и multipart принимают до 8 ссылок известных типов с UUID; дубли объединяются. Запрещённая/неизвестная карточка не прикрепляется.
- Новое сообщение сохраняет только тип/ID и нейтральное название «Карточка CRM». Название, описание, сумма, контакты и URL не сохраняются как снимок карточки.
- Каждому читателю формируется собственное представление по текущим данным и правам. Старые metadata/name вложений не используются как источник сведений.
- Недоступная запись заменяется плашкой **«Карточка недоступна»**, без исходного типа, ID, названия и ссылки. ID самого вложения остаётся для стабильной отрисовки, но не открывает запись.
- История, последнее сообщение канала, ответ API отправки и события WebSocket используют тот же сервис. Цитата из другого канала или удалённого сообщения не возвращается. Автор сообщения отдаётся без email.
- Перед WebSocket-отправкой повторно проверяются сессия и членство. Нельзя разослать всем представление автора сообщения. При ошибке проверки нет отправки сохранённого снимка «на всякий случай».
- Повторяющиеся ссылки в истории загружаются пакетно, один запрос записей на тип, а не на каждое сообщение.
- GET-ответы чата помечены Cache-Control: private, no-store. Файловое API не выдаёт байты ENTITY-вложения или вложения удалённого сообщения.
- Ошибка доставки/чтения после сохранения сообщения с файлами больше не удаляет уже прикреплённые байты. Это не полноценная файловая транзакция/outbox.

## Поведение интерфейса

Используются прежние общие элементы и CSS CRM, без нового оформления экрана.

- Закрытая ссылка отображается с замком и пояснением, без перехода.
- Обновление истории заменяет содержимое даже при прежних ID сообщений: отзыв доступа больше не оставляет старое название.
- Ошибка API очищает старую историю/поиск. Ответы прежнего поиска, канала, закрытого окна и другой сессии не заменяют текущие данные.
- Закрытие/смена пользователя освобождает медиапредпросмотры; запоздавшая загрузка не создаёт новый URL в закрытом окне. Ожидающий доступ к микрофону не начинает запись после закрытия.
- События прежнего socket-соединения и запоздавший счётчик непрочитанных не переходят к новой сессии.
- Навигация принимает только локальные поддерживаемые пути. Задача открывается по ID; клиент/этап пока ведут в соответствующий реестр, а не в конкретную боковую карточку — это оставшийся UX-долг.

Сервер не может «отозвать» сведения, уже увиденные или скопированные сотрудником. Без нового события браузер перепроверяет открытую историю при минутном опросе. Немедленного push-события изменения политики на все устройства пока нет.

## Что остаётся открытым

1. **Обычный текст и файлы чата — самостоятельная передача информации.** Вручную вставленные в сообщение название, телефон, скриншот или документ не редактируются автоматически по правам исходной карточки. Этот пакет не является DLP.
2. Исторические снимки остаются в БД/бэкапах, хотя chat API их больше не выдаёт. Другие административные выгрузки/диагностика должны проверяться отдельно.
3. Текущие TEAM-каналы общие для сотрудников. Название «Продажи» не делает канал закрытым по отделу. Для CHAT-02 нужны сохраняемая политика участников/истории, динамические отделы и отзыв после перевода. Справочник сотрудников не ограничен областью бизнес-карточек.
4. CHAT-01/04: уникальная пара личного чата, cursor-пагинация истории свыше 100 сообщений, эффективные счётчики, версии/идемпотентность отправки, outbox/повтор доставки, прочтение на нескольких устройствах и приёмка PWA.
5. При первом чтении прежний код создаёт/восстанавливает каналы по умолчанию. Перенести инициализацию из GET, исключить автоматическое восстановление архивных каналов; проверить все гонки операций записи и повтор запроса после ошибки ответа.
6. Файлы чата пока не объединены с CRM Drive: отдельные квоты, проверка фактического формата, антивирус, жизненный цикл и безопасная выдача файлов остаются отдельным контрактом. Штатная очистка не заменяет восстановление после аварийного завершения процесса.
7. Отсутствует единый центр уведомлений с гарантированной доставкой/подтверждением. Наличие email-outbox и напоминаний задач не означает готовность всего этого центра.

# Владельцы CSS

В `frontend/nuxt.config.ts` подключаются только три точки входа:

| Файл | Назначение |
|---|---|
| `assets/css/foundation.css` | Общие сбросы, локальные Montserrat WOFF2, базовые переменные. |
| `assets/css/site.css` | Публичная витрина: каталог, карточка, корзина, оформление, кабинет покупателя. |
| `assets/css/admin.css` | Все рабочие пространства сотрудников, чат, модальные окна и кабинет B2B. |

Внутри владельца используются тематические CSS-части. Новую часть импортировать в соответствующей точке входа, а не добавлять четвёртый глобальный файл в Nuxt и не вставлять `<style>` в Vue.

## Где менять дизайн

- Общие внутренние токены, B2B-контролы, поверхности и состояния — `workspace-shared.css`.
- Единая внутренняя типографика — `workspace-typography.css`: Montserrat, 20/14/12 px, веса 600/400. Отдельные цвета обозначают состояние, не новый текстовый стиль.
- Размеры контента, отступы и сворачивание админки — `workspace-layout.css`.
- Внутренние модальные окна и прокрутка — `workspace-dialogs.css`.
- Специальные редакторы — соответствующая тематическая часть, например `catalog-settings.css` или `workspace-banner-editor.css`.
- Витрина не должна использовать внутренние селекторы `.workspace-frame`, `.admin-dialog`, `.b2b-frame`. Внутренние правила не должны менять `.sb-storefront`.

`admin-components.css` и `site-components.css` содержат извлечённые старые компонентные правила с комментариями владельцев. Атрибуты `data-v-ui-*` в шаблонах сохраняют прежнюю область действия scoped-CSS: не удалять их, пока связанные правила не переписаны и не проверены в браузере. Legacy-части сохраняют совместимость; следующий этап — постепенная замена дублирующих правил общими Vue-контролами и токенами, а не добавление бесконечных переопределений.

`main.css`, `design-system.css`, `typography.css` больше не подключаются в Nuxt. Они пока сохранены как исходники старых контрактов, не являются актуальными точками правки дизайна.

Динамические `:style` для бизнес-цветов, количества/прогресса, положения перетаскивания и 3D-эффекта допустимы. Постоянные отступы, шрифты, размеры и оформление элементов задавать CSS-классами. Скрипт `centralize-ui-css.cjs` — уже выполненная одноразовая миграция, не инструмент ежедневного редактирования; повторная запись защищена от потери извлечённых стилей.

## Проверки

Из каталога `frontend`:

```powershell
npm.cmd run check:ui-css
npm.cmd run check:workspace-typography
npm.cmd run check:workspace-dialogs
npm.cmd run check:workspace-operations
npm.cmd run test:visual
```

Playwright использует существующий локальный сервер с актуальной сборкой на порту 3001. Приватные сценарии изолированы от настоящих сохранений и провайдеров; публичные страницы читают локальный каталог. Не запускать браузерную проверку одновременно с пересборкой `.output`: сначала дождаться сборки и перезапустить preview.

# Локальный запуск на Windows

При уже настроенных `.env`, PostgreSQL на порту 5432, Node.js и установленном `redis-server.exe`:

```powershell
# Сначала собрать актуальный код (из корня проекта).
npm.cmd --prefix backend run build
npm.cmd --prefix frontend run build

# Запустить независимые скрытые фоновые процессы.
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

`ExecutionPolicy Bypass` действует только в этом отдельном процессе; настройки политики системы не меняются. Сайт: `http://localhost:3001`, API: `http://localhost:3000/api/v1`. Запуск не выполняет миграции, seed или настоящий вход. Если порт занят, существующий процесс не останавливается и не переиспользуется с новыми настройками: нужно отдельно убедиться, что он обслуживает актуальную сборку.

Журналы и резервная копия существующего `dump.rdb` — `.screenshots/local-services/`. Redis запускается из прежнего корня проекта и читает существующий snapshot, а не пустое хранилище. PostgreSQL используется существующий, не создаётся и не перезапускается. Фоновая автоматика и внешние вызовы интеграций выключены флагами процесса; это локальный режим, не инструкция запуска VPS.

## CORS

Каноническая переменная API: `CORS_ORIGIN`. Поддерживается также прежнее написание `CORS_ORIGINS`. Каноническая непустая переменная имеет приоритет. В production без обеих переменных межсайтовые запросы запрещены — настройки не заменены разрешением любого источника.

Локальный runner задаёт точный список:

```text
CORS_ORIGIN=http://localhost:3001,http://127.0.0.1:3001
```

На VPS указать настоящие HTTPS-origin витрины и рабочего пространства. Проверять переменную **запущенного процесса**: изменение файла само по себе не меняет настройки уже работающего сервера.

## Проверка страниц входа

Из каталога `frontend`:

```powershell
# Внешний вид на ПК/телефоне: без настоящих учётных данных.
node node_modules/@playwright/test/cli.js test tests/visual/login.spec.cjs

# Дополнительно проверить CORS работающего локального API.
$env:PLAYWRIGHT_LOCAL_LOGIN_CORS='true'
node node_modules/@playwright/test/cli.js test tests/visual/login.spec.cjs
Remove-Item Env:\PLAYWRIGHT_LOCAL_LOGIN_CORS
```

CORS-проверка отправляет только `{}` в `/auth/login`; глобальная валидация `LoginDto` возвращает 400 **до** входа и создания сессии. Другие записи, приватные чтения, внешние адреса и WebSocket блокируются. Это доказательство доступности запроса из браузера, не проверка настоящего пароля или полномочий пользователя.

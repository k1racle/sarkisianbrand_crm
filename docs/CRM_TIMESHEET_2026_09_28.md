# TIME-03а — рабочий табель команды и расшифровка

28.09.2026. Продолжение [учёта времени](CRM_WORK_TIME_PLAN_2026_09_24.md), после [исправлений и согласования](CRM_TIME_CORRECTIONS_2026_09_28.md). Этот пакет — рабочий отчёт, не утверждение/закрытие периода, не нормативная форма Т-13 и не расчёт зарплаты.

## Что добавлено

- В «Команда → Рабочее время» отдельная вкладка **«Табель команды»** для проверяющего руководителя. Месяц, текущий отдел, поиск по имени/фамилии, переключатель «Только требующие проверки».
- Строки сотрудников: план, фактическая работа, фактические перерывы, замечания. На ПК — общая шестиколоночная CRM-таблица, на телефоне — те же поля с подписями. Сводка рассчитывается сервером по всей отфильтрованной выборке, не по странице из 25 сотрудников.
- Правая карточка сотрудника: итог месяца, все даты с планом/фактом, раскрытие полных интервалов и перерывов. Ожидающие исправления открываются в уже реализованной карточке согласования; отдельный второй редактор времени не создаётся.
- Выделены незакрытые интервалы, ожидающие исправления, прошедшие дни с планом без отметок, ошибки плана и пересечения факта. День без отметок не обозначается автоматически прогулом. Обычная текущая ночная смена до 24 часов не становится ошибкой из-за перехода через полночь.
- Состояние отчёта подписано **«Рабочий отчёт · не утверждён»**. Нет фиктивной кнопки утверждения или экспорта. План текущий и может измениться после изменения опубликованного графика.

## Исправление полей и стандарт UI

Причина перекоса на присланном скриншоте: общий action-bar центрировал кнопку по высоте подписи и поля вместе. История и состояние заявок переведены на существующий общий `crm-filter-form`, добавлен переиспользуемый модификатор `crm-filter-form--compact`: поле и кнопка 44px, выравнивание по нижнему краю контролов, явный промежуток. На узком экране компактная форма складывается в колонку; от 640px — два элемента в строку. Полные фильтры сохраняют адаптивную сетку 1/2/4 колонки. Новая вкладка использует тот же стандарт. Цвета, шрифты и размеры других типов элементов не менялись, отдельного CSS страницы нет.

## Источники, вычисления и ограничения

- Новых таблиц/миграций нет. API только читает `User`, отделы, опубликованные графики/шаблоны, фактические сессии/перерывы и ожидающие исправления.
- GET `/api/v1/crm/work-time/timesheet/options`, GET `timesheet?month=&departmentId=&search=&view=ALL|ATTENTION&page=`, GET `timesheet/:employeeId?month=`. Ответы private/no-store, транзакция RepeatableRead и единое серверное время для всех строк ответа.
- Единый часовой пояс отчёта — пояс проверяющего из профиля, явно показан в интерфейсе. Месяц/даты одинаковы для всех сотрудников. Исходный пояс каждой отметки сохранён и показан в расшифровке; интервалы в карточке отображаются в поясе отчёта. Ночные интервалы и реальные перерывы обрезаются по границам местной даты, включая DST.
- Для плана используется тот же расчёт постоянных шаблонов и ручных исключений, что для личного месяца. Плановый перерыв без конкретного интервала распределяется пропорционально. Суммы дней дают месячную сумму, точные миллисекунды факта не округляются при сложении; UI отображает целые минуты. Правила кадрового округления ещё не приняты.
- Ожидающая заявка не добавляет фактических часов. Если предложение переносит день в другой месяц, проверка нужна и в месяце исходного снимка, и в месяце предложения. В месячном счётчике каждая заявка/незакрытый интервал учитываются один раз, а не по количеству затронутых дней.
- Пересекающиеся фактические интервалы не складываются в ложный итог: затронутая дата/сотрудник и соответствующий итог выборки показаны прочерком с предупреждением. Аналогично недоступный/некорректный план не считается нулём. Остальные корректные строки доступны для разбора. Пустая корректная выборка имеет нулевые итоги.
- Фильтр отдела — **текущая принадлежность сотрудника**, не историческая организационная структура. Администратор/высшее руководство видят сохранённые записи и неактивных внутренних сотрудников. Руководитель видит только активных сотрудников возглавляемых активных отделов, причём исторический отдел входной записи должен совпадать с текущим. Старые отметки, планы, исправления чужого отдела не участвуют даже в агрегатах/счётчиках/расшифровке. Подотделы автоматически не добавляются.
- Проверяются активность и свежие разрешения `work_time.read` + `work_time.review`, DENY. План требует дополнительно `work_schedule.read`; без него факт доступен, план — нет. Списки, фильтры, options и прямой ID защищены на сервере. Это существующая граница TIME-02б, не новый проект глобальных прав; `DRAFT_ONLY` других модулей не включался.
- Расчёт ограничен 200 сотрудниками, 20 000 сессиями, 10 000 ручными записями плана, 2 000 шаблонами, 5 000 ожидающими исправлениями на выборку. Сверх лимита — запрос уточнить отдел/имя, без тихого обрезания общего итога. Внутри плана сохраняются пределы 1 000 ручных записей/500 шаблонов сотрудника. Большие фоновые отчёты — отдельный будущий пакет.
- Смена фильтра очищает старый результат; ошибка не оставляет на экране старые цифры как новые. Запоздавшие ответы, закрытая карточка и смена учётной записи защищены версиями запросов. Поля фильтра остаются доступными для повторной загрузки.

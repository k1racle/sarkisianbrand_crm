# TIME-02а — личный рабочий день и фактические интервалы

28.09.2026. По просьбе владельца переключиться с длительной доработки прав на рабочие функции. Часть [плана учёта времени](CRM_WORK_TIME_PLAN_2026_09_24.md) и BOX-05, а не завершение табеля или расчёта зарплаты.

Позднее в тот же день реализован [TIME-02б](CRM_TIME_CORRECTIONS_2026_09_28.md): исправления, пропущенные дни с согласованием, личный план/факт и незакрытые дни команды. Ниже сохранён исходный срез TIME-02а; прежнее «корректировки не реализованы» относится к нему, не к текущей версии. Далее — командный табель, утверждение/закрытие и Excel.

## Что доступно сотруднику

- «Команда → Рабочее время», `/crm/work-time`; тот же блок управления в «Моём дне».
- Начать рабочий день, начать перерыв, вернуться к работе, завершить день с подтверждением. Завершение во время перерыва закрывает и перерыв.
- Работа и перерывы сегодня, работа за текущий открытый день, дата начала. Несколько завершённых дней/интервалов за сутки складываются в итог, открытый может быть только один.
- История по месяцам с раскрытием перерывов. Итоги месяца считают только реально попавшую в месяц часть ночного интервала и его перерывов.
- Если день не закрыт больше 24 часов, показывается предупреждение. День не завершается автоматически и не заменяется плановыми часами.
- Обновление/другой браузер получают сохранённый день с сервера. Автообновление раз в 30 секунд, при возврате во вкладку/окно и восстановлении сети; не WebSocket-присутствие в реальном времени.
- При потере ответа после записи есть «Проверить сохранение»: повторяется тот же запрос. Успех не показывается до подтверждения. Офлайн-отметок и фоновой отправки старых действий нет.

## Данные и расчёт

Аддитивная миграция `20260928140000_crm_work_time`: `CrmWorkSession`, `CrmWorkBreak`, `CrmWorkTimeEvent`. Применена только к проверенной существующей БД `localhost:5432/sarkisian_brand`. Других ожидающих миграций не было. Ни таблицы, ни записи графиков не удалялись/переписывались.

- Начало/конец берутся из часов БД после блокировки сотрудника. Клиент не передаёт время, длительность или employeeId.
- Часовой пояс текущего профиля сохраняется при начале дня; открытый день продолжает использовать сохранённый пояс. Месячные итоги считаются в актуальном поясе профиля, явно указанном в интерфейсе.
- Интервалы хранятся как моменты времени, длительность — фактическое прошедшее время, включая переходы DST. Перерывы вычитаются. Расчёты сохраняют миллисекунды; показ часов/минут не является зарплатным округлением.
- Одна открытая сессия сотрудника и один открытый перерыв сессии защищены частичными уникальными индексами PostgreSQL. Все команды сотрудника сериализуются блокировкой строки User.
- `requestKey` уникален для сотрудника; изменение тела под прежним ключом даёт конфликт. Повтор старого START после завершения не открывает новый день. Другой ключ при уже открытом дне также не создаёт дубль.
- Версия предотвращает команду по состоянию другого устройства. Сессия, перерыв, событие и аудит меняются одной транзакцией. При сбое аудита изменение откатывается.
- Нельзя закончить день раньше последней отметки или начать новый раньше окончания прежнего при переводе часов сервера назад.

API: `GET /crm/work-time/current`, `GET /crm/work-time?month=YYYY-MM`, `POST /crm/work-time/actions`. Ответы `private, no-store`. Месячная выдача ограничена 500 интервалами с явной ошибкой превышения, не молча обрезанными итогами. Отдельного постраничного реестра команды в этой версии нет.

Новые минимальные разрешения `work_time.read` и `work_time.track` назначены внутренним ролям для **своего** времени. Нельзя передать ID другого сотрудника; даже администратор получает здесь только собственные отметки. Клиентские аккаунты, неактивные сотрудники и персональные DENY не получают запись. Это не продолжение настройки глобальных профилей доступа: они остаются DRAFT_ONLY.

## Общий интерфейс

`CrmWorkClock` повторно используется на двух экранах. Панели, кнопки 44 px, статусы, показатели и поля — существующие классы CRM, без отдельного CSS экрана. Mont для заголовков, Montserrat для текста. Общий `crm-section-inset` задаёт внешние отступы в старой странице без собственных page gutters. Отдельный CSS для часов не добавлен. Навигация: прежние девять групп, 50 маршрутов; новый Clock3 в «Команде».

## Проверки

- Backend: сборка и **87 наборов / 1809 тестов** прошли, из них **50 тестов** нового блока. Расчёты/полночь/DST/граница месяца, повтор/версии, сохранение/откат и недоступность чужого дня.
- `node scripts/work-time-local-check.cjs` (запуск из backend) — **14 проверок** настоящего локального PostgreSQL через сервис: команды, частичный уникальный индекс, события/аудит и ночной переход сентября в октябрь. Весь синтетический сотрудник и отметки откатываются одной внешней транзакцией; отсутствие остатков проверено. Это не тест независимых конкурентных соединений и не внешняя интеграция.
- Общие элементы: **239 компонентов / 828 контролов**, проверка владения CSS, 18 проверок CRM-навигации и 31 workspace-навигации прошли.
- `node scripts/crm-work-time-mock.cjs` из frontend — прошёл на **390/1440 px**: «Мой день» → история, старт, потеря ответа после сохранения и повтор с прежним ключом, перерыв/перезагрузка/возврат, конфликт другого устройства, завершение и история, только просмотр, ошибка загрузки. Шрифты сравнены с «Моим днём», кнопки 44 px, без переполнения страницы. API перехвачены, кадровые отметки на сервер не отправляются.
- Итоговая frontend-сборка с prebuild прошла (GOMAXPROCS=2); сценарий времени повторён после выравнивания отступов. Регрессия `crm-work-schedule-mock.cjs` также прошла на 390/1440 px: три вкладки, счётчики людей без выходных, карточки и изменения графиков. Скриншоты `frontend/.screenshots/crm-work-time/` просмотрены. Локальные backend/frontend перезапущены с новыми сборками, `/crm/work-time` отвечает HTTP 200; журналы ошибок запуска пусты.

Внешние обмены, почта, фоновые задачи и медиасервер не запускались. Production и DNS не менялись. Известные предупреждения Nuxt о старых именах маршрутов, URL шрифтов/чанках и package mapping остаются отдельным долгом упаковки.

# BOX-01б4а — доступ к заказам и поддержке

Дата: 28.09.2026. Статус: ограниченный пакет реализован и проверен локально. Основной план: [CRM_BOXED_RELEASE_PLAN_2026_09_24.md](CRM_BOXED_RELEASE_PLAN_2026_09_24.md).

Это не завершение BOX-01, не готовность всей CRM к запуску и не включение изоляции отделов. Рабочий источник прав сохраняет **legacy COMPANY и персональные запреты**, новые профили остаются **DRAFT_ONLY**. Миграций, изменения ролей сотрудников и массового назначения ответственных в этом пакете нет.

## Что изменено

- OMS: сводка, список с пагинацией, старый список, карточка по ID/номеру и изменение статуса получают текущего сотрудника. Предикат области применяется до выборки, поиска, подсчёта и агрегации. Чтение и изменение проверяются независимо; write не расширяет read.
- Маркетплейсы: список/сводка и изменение заказа используют отдельные `marketplace.read/write`. Канал проверяется отдельно: известный ID WEB/B2B-заказа не открывает доступ через API площадки. Сохранены блокировка строки и повторная проверка текущего статуса.
- Поддержка: список, сводка, отдельный GET карточки, создание, изменение, комментарии и выбор исполнителя используют текущего сотрудника и области. Отсутствующие/чужие/удалённые заявки недоступны; переназначение вне результирующей read/write-области откатывается. Снятие исполнителя требует обеих областей COMPANY. Целевой сотрудник должен быть активен и иметь права поддержки.
- Сервер возвращает `canWrite` каждой записи. B2B, маркетплейсы и поддержка используют его вместе с общим разрешением для полей, кнопок, обработчиков и ПКМ. Ошибка получения полной B2B-карточки блокирует сохранение оставшегося снимка списка. Изменение настроек площадки в UI отдельно требует `marketplace.configure`.
- Из ответов OMS исключены guest/checkout-хэши, сырые payload площадки, служебные снимки цен и метаданные платежей. Контакты/организации/обращения выдаются минимальными проекциями с собственными ограничениями; недоступные связи и их ID маскируются. Поиск по организации не раскрывает закрытую организацию.
- Customer 360 теперь применяет узкие OMS/Helpdesk-области к истории, счётчикам и суммам. Это уточняет прежний временный запрет всей такой истории при не-COMPANY области из BOX-01б3.
- Мутации выполняются в Serializable-транзакции с общей блокировкой изменений структуры отделов; чтение — RepeatableRead. Конфликты сериализации/уникальности возвращаются без внутренних идентификаторов. Существующая финансовая логика переходов не заменялась.
- EXECUTIVE разрешён в списках ролей контроллеров и навигации поддержки/площадок, **только при наличии соответствующего разрешения**. Новые разрешения этой роли автоматически не выдавались.

## Значение областей

| Область | Заказ | Обращение |
| --- | --- | --- |
| OWN | Ответственный `managerId` | Исполнитель `assignedToId` |
| PARTICIPATING | Ответственный либо исполнитель связанной неотменённой задачи | Исполнитель либо сотрудник-заявитель |
| DEPARTMENT | Текущий отдел ответственного | Текущий отдел исполнителя |
| DEPARTMENT_TREE | Отдел и действующие подотделы | Отдел и действующие подотделы |
| SELECTED_DEPARTMENTS | Явно выбранные действующие отделы | Явно выбранные действующие отделы |
| COMPANY | Все записи разрешённого домена | Все обращения разрешённого домена, кроме корзины |

`Order.userId` — покупатель, не владелец служебной записи. Заказы без менеджера при OWN/DEPARTMENT не распределяются автоматически. При переходе на активные профили нужен отдельный управляемый этап распределения исторических данных. Участие через связанные задачи и все состояния их архива/корзины подлежат сквозной проверке до активации профилей.

## Публичная поддержка

Анонимная форма больше не вызывает внутреннее создание заявки. Отдельный DTO допускает тему, описание, имя, email и источник B2C/B2B. Нельзя передать назначение, приоритет, служебный источник, ID заказа/клиента/организации. Данные дополнительно перечислены явно при сохранении.

Email не считается доказательством личности: публичная форма не ищет частные записи, не создаёт автоматически клиента и не связывает заявку с существующими данными. Ответ содержит только `{ accepted, number }`, без внутренних ID и карточек. Для маршрута установлен лимит 3 запроса в минуту на уровне Throttler. Проверка IP за reverse proxy, распределённый rate-limit, антиспам и подтверждение контакта — отдельная серверная приёмка/доработка.

Тексты интерфейса уточнены: комментарий **сохраняется**, но не отправляется клиенту. SLA пока считается по приоритету в календарных часах, без рабочего календаря. При переоткрытии очищаются даты закрытия/решения.

## Фоновый импорт

Инициатор передаётся обработчику из серверной записи `JobRun`, а не из произвольного поля payload. Проверка выполняется перед постановкой задания, при старте обработчика и внутри каждой операции импорта. Отсутствующий или лишённый прав инициатор не заменяется администратором.

Поскольку импорт автоматически сопоставляет/создаёт клиентов и обновляет заказ по внешнему ID, пока он разрешён только при COMPANY для **marketplace.read, marketplace.write, customers.read и customers.write**. Это намеренное ограничение: права обычного менеджера площадки не расширяются молча. Исторические задания без инициатора потребуют авторизованного повторного запуска. Модель служебной учётной записи планового импорта, отмена/возобновление, идемпотентность всего пакета и права на просмотр/повтор заданий остаются отдельной работой.

- Backend: `npm.cmd run build` — успешно; финальный `npm.cmd test -- --runInBand` — **79 наборов / 1642 теста**, все прошли. Новые проверки: шесть областей, DENY, независимость read/write, прямые ID/номер, фильтры и счётчики, безопасные проекции, связанная история Customer 360, назначение/откат, публичный DTO/ответ, инициатор фонового задания. Зависимости подменены, реального обмена нет.
- Frontend: `npm.cmd run build`, включая prebuild, — успешно при повторном запуске с `GOMAXPROCS=2`. Первый параллельный запуск завершился аварией esbuild; повторная сборка проверена, системные переменные постоянно не менялись. Предупреждения о совпадающих именах legacy marketplace-маршрутов, runtime URL шрифтов и крупных чанках остаются.
- `workspace-navigation-check.cjs` — 31 проверка; `crm-element-contract.cjs` — 48 владельцев / 817 контролов; `workspace-operations-check.cjs --crm-only` — 8 групп. Устаревшие mock-ответы дополнены явными `ready` и `canWrite`, рабочая защита не ослаблялась ради тестов.
- `crm-operational-access-mock.cjs`: 390/1440 px, три экрана, режимы просмотра/изменения, поля, кнопки и ПКМ; 8 подменённых изменений суммарно, **0 реальных записей и внешних запросов**.

# HTTP-контракт SARKISIAN ↔ 1С:КА

Версия: `v1`. Контракт предназначен для HTTP-сервиса, опубликованного в конкретной базе 1С:КА. Пути настраиваются в «Настройки экосистемы → Интеграции → 1С» и не зашиты в коде платформы.

## Ответственность систем

- 1С:КА владеет номенклатурой, SKU/артикулом, базовой ценой и фактическим остатком.
- Платформа владеет контентом и SEO карточки, B2B-календарём и канонической историей заказа.
- Все заказы сначала нормализуются в едином OMS платформы, затем передаются в 1С: сайт (`WEB`), B2B-кабинет (`B2B`), Wildberries, Ozon, Яндекс Маркет, Мегамаркет и ручной ввод (`MANUAL`).
- 1С создаёт или обновляет «Заказ клиента», назначает организацию и склад, формирует складское задание на сборку и делает его доступным кладовщику в рабочем месте ТСД. Повторная передача одного `id` не должна создавать второй документ или второе задание.
- Платформа хранит каноническую историю заказа и показывает состояние обмена; 1С владеет складским документом, фактической сборкой и движениями товара.

## Безопасность

- Только HTTPS в рабочем режиме.
- Basic Auth: отдельный технический пользователь 1С с минимальными правами.
- Опциональная HMAC SHA-256 подпись: `X-Sarkisian-Signature = hex(hmac(secret, timestamp + "." + rawBody))`.
- Метка времени: `X-Sarkisian-Timestamp`, миллисекунды Unix. На стороне 1С рекомендуется окно не более 5 минут.
- Корреляция: `X-Correlation-Id`; значение необходимо писать в журнал регистрации 1С.
- Ответы — JSON в UTF-8. Успех — HTTP 2xx, ошибка — HTTP 4xx/5xx с `{ "error": "понятное описание" }`.

## 1. Проверка соединения

`GET /hs/sarkisian/v1/health`

```json
{
  "status": "ok",
  "system": "1С:Комплексная автоматизация",
  "database": "рабочая база",
  "version": "1.0"
}
```

## 2. Номенклатура, цены и остатки

`GET /hs/sarkisian/v1/products`

```json
{
  "products": [
    {
      "externalId": "уникальная ссылка/UUID 1С",
      "sku": "SB-LIVE-010",
      "nameRu": "Гель скоростной густой № 111, 30 мл",
      "slug": "gel-skorostnoy-111-30-ml",
      "price": 1440,
      "stock": 25
    }
  ]
}
```

Обязательны `externalId`, `sku`, `nameRu`, `price`. `slug` желательно передавать; при отсутствии он может быть сформирован из артикула. Денежные значения передаются числами в рублях, остаток — целым числом.

## 3. Контрагенты

`GET /hs/sarkisian/v1/counterparties`

```json
{
  "counterparties": [
    {
      "externalId": "уникальная ссылка/UUID 1С",
      "name": "Студия красоты «Форма»",
      "legalName": "ООО «Студия Форма»",
      "inn": "7700123456",
      "kpp": "770001001"
    }
  ]
}
```

Ключ синхронизации — `externalId`. ИНН используется для сверки, но не заменяет внешний ID 1С.

Ответ 1С:

```json
{
  "acceptedIds": ["канонический UUID заказа платформы"],
  "externalIds": {
    "канонический UUID заказа платформы": "UUID документа Заказ клиента в 1С"
  },
  "warehouseDocumentIds": {
    "канонический UUID заказа платформы": "UUID складского задания 1С"
  },
  "errors": []
}
```

1С обязана искать ранее созданный документ по `id` платформы и обновлять его, а не создавать дубликат. Этот ID хранится в дополнительном реквизите документа и является ключом идемпотентности. Платформа помечает выгруженными только значения из `acceptedIds` или элементы `orders` с `accepted: true`.

Обработка каждого принятого заказа на стороне расширения 1С:

1. Найти «Заказ клиента» по каноническому `id`, при отсутствии — создать.
2. Сопоставить организацию, контрагента, соглашение, номенклатуру и склад по настроенным ID/SKU.
3. Заполнить источник и номер внешнего канала, цены, скидки, оплату и доставку.
4. Провести документ по правилам рабочей базы.
5. Если `requiresPicking = true`, создать либо актуализировать складское задание/расходный ордер, доступный в используемом рабочем месте ТСД.
6. Вернуть UUID обоих документов. Ошибка одной строки не должна подтверждать этот заказ в `acceptedIds`.

## 5. Получение статусов сборки

Платформа опрашивает 1С методом `GET /hs/sarkisian/v1/order-statuses`. Метод может возвращать только изменения после курсора, если этот механизм будет добавлен в расширение 1С.

```json
{
  "statuses": [
    {
      "platformOrderId": "канонический UUID заказа платформы",
      "external1CId": "UUID Заказа клиента в 1С",
      "status": "PICKING",
      "warehouseDocumentId": "UUID складского задания 1С",
      "trackingNumber": null,
      "comment": "Кладовщик начал сборку на ТСД",
      "occurredAt": "2026-09-15T09:00:00.000Z"
    }
  ]
}
```

Поддерживаемые этапы: `RECEIVED`, `ACCEPTED`, `READY_FOR_PICKING`, `PICKING`, `PICKED`, `PACKED`, `READY_TO_SHIP`, `SHIPPED`, `DELIVERED`, `CANCELLED`, `REFUNDED`. Платформа не откатывает завершённый заказ на более ранний этап.

## 6. Мгновенная передача статуса из 1С/ТСД

Для событийной схемы 1С вызывает `POST {platformBaseUrl}/api/v1/1c-webhook/order-statuses` с тем же массивом `statuses` и заголовком `X-Integration-Key`. Значение заголовка равно секрету `exchangeSecret` из настроек экосистемы. Повторная передача одного статуса безопасна.

Если callback временно недоступен, 1С должна поставить событие в свою очередь повторов. Периодический `GET order-statuses` остаётся страховочным механизмом.

## Настройки подключения

- `baseUrl` — корень опубликованной базы/HTTP-сервиса;
- `username` — технический пользователь;
- секрет `password` — пароль;
- секрет `exchangeSecret` — обязательный HMAC-ключ исходящих запросов и ключ входящих статусов;
- `healthPath`, `productsPath`, `counterpartiesPath`, `ordersPath`, `orderStatusesPath` — реальные пути публикации;
- `warehouseId` — склад 1С, на котором формируется сборка;
- `organizationId` — организация 1С, от имени которой создаётся заказ;
- `orderType` — используемый в базе вид документа, по умолчанию «Заказ клиента»;
- `requestTimeoutMs` — таймаут 2–120 секунд.

## Приёмка реальной базы

1. Проверить health-check из админки.
2. Импортировать одну контрольную номенклатуру и сверить цену/остаток.
3. Сверить одного контрагента по внешнему ID и ИНН.
4. По одному разу выгрузить заказы сайта, B2B, каждого маркетплейса и ручной заказ; найти их в 1С.
5. Убедиться, что для каждого заказа создано ровно одно складское задание и оно появилось на тестовом ТСД кладовщика.
6. Запустить тот же обмен повторно и подтвердить отсутствие вторых заказов и складских заданий.
7. На ТСД пройти этапы начала сборки, подбора и упаковки; сверить статусы и временные метки в OMS.
8. Изменить заказ в платформе и проверить обновление существующего документа 1С.
9. Отключить 1С, создать заказ, восстановить соединение и проверить автоматическую довыгрузку из очереди.
10. Сверить суммы, количества, остатки и журнал корреляционных ID.
